# 985gmgn助手 v0.46.109

## 本版重点

本版修复「检查更新失败：无法连接 GitHub，请检查网络后重试」，让连不上 GitHub 的用户也能正常检查和一键升级。

- **问题根源**：检查更新并不是由浏览器发起的。插件把这件事交给本机的独立进程 `985gmgn-updater.exe`，而它走的是 **Windows 系统代理**（Internet 选项里的那个），浏览器上的代理、加速插件或只对浏览器生效的网络设置，它一概看不见。于是会出现「浏览器能正常打开 GitHub，插件却说连不上」这种看起来自相矛盾的情况。更麻烦的是，以前这条路是唯一的一条，连不上就彻底没有退路。
- **修复**：检查版本、下载安装包、获取校验文件三步各增加官网兜底。GitHub 连不上时，改从 bettergmgn.com 取版本号、安装包和 SHA256 校验文件；历史版本回退同样适用，官网保留了历史安装包。
- **只在连不上时兜底**：草稿版、预发布版、缺少安装包这类是有意拒绝安装的情况，不会因为换一个下载源就被绕过去。下载地址一律由版本号自己拼出，不采用服务端响应里给的路径，并强制落在官网的下载目录下。
- **校验只增不减**：GitHub 接口通、但下载域名不通时，会用接口给出的官方 digest 校验从官网下载的安装包。两边都拿不到校验信息则直接拒绝安装，宁可装不上也不装没校验过的包。
- **错误提示分清楚了**：以前限流、证书失败、404 全被并成同一句「无法连接 GitHub」，照着提示查网络自然查不出问题。现在能拿到状态码就直接报 HTTP 状态码；彻底连不上时明确提示更新器走的是 Windows 系统代理，浏览器上的代理对它无效。

## 安装方法

已有用户可在插件设置中检查更新并使用一键升级；新用户下载安装器，或解压 ZIP 后在浏览器中加载扩展。扩展 ID 与配置位置不变，特别关注、人物策略、标注名单、筛选条件、徽章开关和声音设置全部保留。

如果你正卡在「无法连接 GitHub」而升不上来，请先从官网下载安装器手动覆盖安装一次。装上这一版之后，后续的检查与升级就会在 GitHub 不通时自动改走官网，不需要再手动下载。

## 使用说明

更新相关的操作位置没有变化，仍在插件设置页的版本管理里：检查更新、一键升级、跳过本次更新、回退历史版本。兜底是自动的，没有新增开关，也不需要任何配置。

若检查仍然失败，请按新的提示分辨原因：提示里出现 HTTP 状态码，说明网络是通的，是服务端返回了错误，稍后重试即可，常见于短时间内反复点击检查触发的接口限流；提示里说两个源都连不上，则是本机网络问题，请检查 Windows 的系统代理设置，注意浏览器插件形式的代理不会对更新器生效。

安装器自检新增了六条断言覆盖本次改动，包括下载地址拼装、拒绝非官网域名、拒绝非下载目录路径、拒绝非法版本号，以及没有校验信息时拒绝安装。这些断言在每次打包时都会运行，不通过则不会产出安装器。

## 更新方式

从 v0.46.108 升级到 v0.46.109。继续提供跳过本次更新与历史版本回退。升级不改动任何已有设置，不改变交易参数，也不会自动开启任何功能。

已经打开的页面需要重新加载后才使用新的内容脚本。本版只改动更新器与版本管理相关逻辑，FOMO 浮窗、聚合监控、重点提醒、方向着色、声音提醒、徽章开关及其余既有能力完全不受影响。

## 安全与隐私

兜底只在 GitHub 连不上时触发，访问的是插件官网自己的下载目录，不引入任何第三方镜像或加速服务，也不上传任何本机信息。安装包在解压前逐字节校验 SHA256，校验不过一律拒绝安装并保留旧版本；安装前仍会备份当前版本。

需要说明一个权衡：当 GitHub 完全不通时，安装包与校验值都来自官网，等于把官网当作与 GitHub 同等的分发信任源。官网本来就是新用户下载安装器的入口，因此信任面并没有实质扩大。插件不读取钱包私钥、不发起签名、不执行交易。详见仓库完整说明与 PRIVACY.md。
